# 🔧 Task 26 — تب توضیحات/دیدگاه‌ها + دسته‌بندی درختی (دسته فروشگاه) + فیلتر پروفایل + رفع باگ‌ها

## ۱) تب‌های «توضیحات» و «دیدگاه‌ها» در صفحه پکیج و محصول

**مشکل:** توضیحات ممکن است خیلی طولانی باشد و دیدگاه‌ها گم شوند زیر آن؛ شمارنده دیدگاه‌ها هم دیده نمی‌شد.

تغییرات:
- ✅ در **صفحه پکیج** (`package-show.blade.php`): کارت «توضیحات پکیج» از ستون کنار حذف شد و بخش پایین صفحه به یک **کارت تب‌دار** تبدیل شد:
  - تب «توضیحات پکیج» (content کامل با `rich-content`)
  - تب «دیدگاه‌ها» با **شمارنده دیدگاه‌های تأییدشده** (badge عددی فارسی)
- ✅ در **صفحه محصول** (`product-show.blade.php`): سکشن توضیحات + سکشن دیدگاه‌ها ادغام شدند در همان کارت تب‌دار (تب «توضیحات پروژه» / «دیدگاه‌ها» با شمارنده).
- پیاده‌سازی با **Alpine.js** (`x-data="{ shopTab: 'description' }"`) — بدون رفت‌وبرگشت سرور؛ کامپوننت فرزند `livewire:shop.comment-section` داخل پنل تب دیدگاه‌ها mount می‌ماند (state فرم دیدگاه حفظ می‌شود).
- دسترسی‌پذیری: `role="tablist" / role="tab" / role="tabpanel"` + `:aria-selected`.
- مدل‌ها: متد `approvedCommentsCount()` به `Package` اضافه شد (همتای `Product`).

## ۲) دسته‌بندی درختی (فرزند/والد) — برای «انتخاب دسته فروشگاه» هنگام نصب روی وردپرس

**نیاز:** کاربر می‌خواهد وقتی پکیج روی وردپرس (ووکامرس) نصب می‌شود، دسته فروشگاه (با ساختار درختی) به‌درستی انتخاب/ساخته شود.

### دیتابیس
- مایگریشن جدید `2026_10_18_000001_add_parent_id_to_categories_table.php`:
  ستون `parent_id` (خودارجاع، `nullOnDelete`) + ایندکس `(type, parent_id)`.
  ⚠️ **بعد از pull حتماً `php artisan migrate` اجرا شود.**

### مدل `Category`
- رابطه‌ها: `parent()`, `children()` + scope `roots()`.
- `subtreeIds(int $rootId)` → شناسه‌های خود دسته + همه زیردسته‌ها (BFS با محافظ حلقه، MAX_DEPTH=۵).
- `inSubtree($rootId, $candidateId)` → جلوگیری از حلقه در انتخاب والد.
- `pathLabel()` → «والد › فرزند».
- `flatOptions($type, $excludeId)` → گزینه‌های تختِ درختی برای سلکت‌های پنل (با تورفتگی «— » و بریدن زیردرختِ دسته در حال ویرایش).
- `shopTree($type)` → درختِ فروشگاه: دسته‌های فعالِ یک نوع، مرتب سلسله‌مراتبی + دو attribute:
  `shop_count` (تعداد تجمیعی خود + زیردرخت) و `hierarchy_label` (مسیر کامل).

### پنل مدیریت
- **مدیریت دسته‌بندی‌ها** (`Livewire\Categories\Index`):
  - فیلد «دسته والد» در مودال (فقط هم‌نوع؛ تغییر نوع، والد را پاک می‌کند — `updatedFormType`).
  - اعتبارسنجی: والد باید هم‌نوع باشد و نمی‌تواند خود دسته/زیردسته‌هایش باشد.
  - جدول: ستون جدید «والد» + تورفتگی و آیکون برای زیردسته‌ها.
  - حذف دسته‌ای که زیردسته دارد ممنوع است (پیام خطای شمرده‌شده).
  - مرتب‌سازی: `type → COALESCE(parent_id, id) → sort_order → name` (والد و فرزندانش کنار هم).
- **فرم پکیج/محصول**: سلکت دسته‌بندی حالا درختی است (`flatOptions`) در هر ۳ محل: `Packages/Index`، `Packages/Show`، `Products/Index`.

### فروشگاه فرانت
- فیلتر دسته‌بندی در صفحه پکیج‌ها و پروژه‌ها **درختی** شد: انتخاب دسته والد → نمایش پکیج‌های خودش + همه زیردسته‌ها (`subtreeIds`).
- چیپ‌های فیلتر (`filter-bar.blade.php`): زیردسته‌ها با نشانگر مسیر («قالب ↰ فروشگاهی») و شمارنده تجمیعی (`shop_count`) نمایش داده می‌شوند؛ ترتیب چیپ‌ها سلسله‌مراتبی است.

### API v1 (برای افزونه وردپرس)
- 🆕 `GET /api/v1/categories?type=package|product` (با همان احراز update_code + X-Project-Url):
  درخت کامل دسته‌های فعال `{ id, name, slug, description, children[] }` — افزونه می‌تواند درخت دسته فروشگاه را نشان دهد/بسازد.
- خروجی `GET /api/v1/packages` و `GET /api/v1/packages/{slug}` فیلد جدید **`category_details`** دارد:
  ```json
  {
    "id": 5, "name": "فروشگاهی", "slug": "shop-themes",
    "parents": [ { "id": 3, "name": "قالب", "slug": "themes" } ],
    "path": "قالب › فروشگاهی",
    "path_slugs": ["themes", "shop-themes"]
  }
  ```
  با این ساختار افزونه می‌تواند هنگام نصب، همان زنجیره دسته را در ووکامرس بسازد/پیدا کند (term path مشابه وردپرس). `parents` از ریشه تا والدِ مستقیم است؛ `categoryModel.parent` در هر دو endpoint با eager-load آمده (بدون N+1).

## ۳) پروفایل مشتری: فیلتر لایسنس + حذف پکیج‌های تکراری + شمارنده

- **تب لایسنس‌ها**: نوار فیلتر جدید — جستجو (نام پکیج یا کلید لایسنس، live با debounce) + فیلتر وضعیت (فعال/منقضی/لغو شده). حالت خالیِ فیلتردار پیام مخصوص خودش را دارد.
- **تب پکیج‌های من**: اگر مشتری یک پکیج را چند بار خریده/تمدید کرده باشد فقط **آخرین خریدِ هر پکیج** نمایش داده می‌شود (`MAX(id) GROUP BY package_id`).
- **شمارنده‌ها**: تب «پکیج‌های من» تعداد پکیج‌های متمایز خریده‌شده و تب «لایسنس‌ها» تعداد کل لایسنس‌ها را به‌صورت badge نشان می‌دهند؛ کارت آماری «پکیج خریده‌شده» هم `COUNT(DISTINCT package_id)` شد (سازگار با dedupe).

## ۴) رفع باگ لاگ پیامک

- ❌ خطا: `Undefined variable $records (View: .../livewire/sms/logs.blade.php)` — دلیل: در جدول از متغیر خام `$records` استفاده شده بود در حالی که `records` یک `#[Computed]` است (فقط وقتی لیست خالی نبود خطا می‌داد).
- ✅ اصلاح شد به `$this->records` (هم‌راستا با دو استفاده دیگر در همان فایل).

## ۵) اسکرول منوی پنل روی آیتم فعال

- سایدبار پنل مدیریت حالا بعد از هر ناوبری (wire:navigate) اسکرول می‌خورد تا **آیتم فعال منو** (`a[aria-current]`) در دید باشد:
  `x-init="$nextTick(() => $el.querySelector('a[aria-current]')?.scrollIntoView({ block: 'center' }))"` روی `<nav>` — با wire:navigate دام re-init می‌شود و این x-init بعد از هر جابه‌جایی صفحه اجرا می‌شود.

## چک‌لیست تست دستی

1. `php artisan migrate` (مایگریشن parent_id)
2. پنل → دسته‌بندی‌ها: یک دسته «قالب» بساز، بعد زیردسته «فروشگاهی» با والد «قالب» — تورفتگی و ستون والد را ببین؛ تلاش برای انتخاب «قالب» به‌عنوان والدِ خودش → خطا؛ حذف «قالب» با داشتن فرزند → پیام خطا.
3. فرم پکیج: سلکت دسته‌بندی درختی است («— فروشگاهی»).
4. فروشگاه → پکیج‌ها: چیپ «قالب» تعداد تجمیعی دارد؛ کلیک روی آن پکیج‌های «فروشگاهی» را هم نشان می‌دهد.
5. صفحه پکیج/محصول: تب توضیحات ↔ دیدگاه‌ها؛ عدد کنار تب دیدگاه‌ها = تعداد تأییدشده‌ها.
6. پروفایل مشتری: تب لایسنس‌ها فیلتر جستجو/وضعیت؛ تب پکیج‌ها بدون ردیف تکراری؛ badge تعداد روی تب‌ها.
7. پنل → لاگ پیامک: بدون خطای `$records` (چه خالی چه پر).
8. افزونه/کلاینت: `GET /api/v1/categories` درخت را می‌دهد؛ `GET /api/v1/packages` فیلد `category_details` دارد.
