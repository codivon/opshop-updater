# آپدیت‌سنتر — پنل مدیریت پروژه‌ها، پکیج‌ها، محصولات و لایسنس‌ها

پنل مدیریت مدرن بر پایه **Laravel 13 + Livewire 3** با تجربه SPA (بدون ریلود صفحه)، طراحی بازنویسی‌شده با **Tailwind CSS 4**، RTL کامل و فونت وزیرمتن.

## امکانات

- **داشبورد**: آمار زنده، چارت‌های SVG سبک، آخرین خریدها/آپدیت‌ها، لایسنس‌های در حال انقضا
- **پروژه‌ها / آپدیت‌ها**: CRUD کامل با مودال + آپلود فایل ZIP
- **پکیج‌ها**: کارت‌گرید، صفحه جزئیات با تب‌های (اطلاعات / نسخه‌ها / پلن‌های قیمت / لایسنس‌ها / گالری) + فیلتر دسته‌بندی ساختاریافته
- **محصولات (پروژه‌های قابل‌فروش)**: فروش مستقیم اسکریپت/قالب/اپلیکیشن با خرید مهمان بدون ثبت‌نام — صفحه تکی با دیدگاه‌ها (تأیید مدیر)، نسخه‌بندی + changelog، دانلود ZIP توکنی یک‌بارمصرف ۱۵ دقیقه‌ای و پیگیری خرید با شماره تراکنش
- **دسته‌بندی‌ها**: جدول مشترک برای محصولات و پکیج‌ها (قابل مدیریت از پنل) + فیلتر دسته/قیمت/جستجو/مرتب‌سازی در هر دو بخش فروشگاه
- **دیدگاه‌ها**: ثبت مهمان روی صفحه محصول → تأیید/رد/حذف از پنل (با نشان تعداد در انتظار در منو)
- **نسخه‌های پکیج/محصول**: آپلود ZIP + هش SHA256 + محدودیت نسخه/PHP/Laravel + وابستگی‌های JSON
- **لایسنس‌ها**: صدور خودکار، ابطال/فعال‌سازی، منقضی‌کردن قدیمی‌ها، تاریخچه توکن دانلود
- **خریدها**: تراکنش‌ها + وضعیت پرداخت + خلاصه درآمد
- **مشتریان / اشتراک‌ها**: CRUD + تمدید اشتراک + کد آپدیت با دکمه کپی
- **گزارش‌ها**: ۴ تب تحلیلی (نمای کلی / مشتریان / آپدیت‌ها / فروش) با فیلتر تاریخ
- **لاگ‌ها**: نمایش ترمینالی با سطح ERROR/WARNING/INFO + دانلود + پاک‌سازی
- **تنظیمات + درگاه‌ها**: تنظیمات عمومی/ایمیل + پیکربندی ۱۱ درگاه پرداخت ایرانی
- **API عمومی مشتریان** (`routes/api/v1.php`): بدون تغییر باقی مانده — چک آپدیت، خرید، لایسنس، دانلود توکنی

## ویژگی‌های فنی

- `wire:navigate` برای ناوبری SPA + نوار پیشرفت + انیمیشن‌گذار صفحات
- دارک‌مود (کلاس `dark` + ذخیره در localStorage) بدون فلش اولیه
- سایدبار جمع‌شونده + دراور موبایل
- توست‌های سراسری با `WithToasts` trait (رویداد Livewire → Alpine Store)
- صفحه‌بندی RTL فارسی (اورراید `livewire::tailwind`)
- آیکون‌های Lucide به‌صورت inline (بدون وابستگی)
- تاریخ شمسی با morilog/jalali + اعداد فارسی
- مودال‌های Livewire (entangle) برای همه فرم‌ها

## نصب

```bash
composer install
cp .env.example .env      # سپس APP_KEY و DB را تنظیم کنید
php artisan key:generate
touch database/database.sqlite   # اگر از sqlite استفاده می‌کنید
php artisan migrate
php artisan storage:link

npm install && npm run build     # یا bun
php artisan serve
```

> داده نمونه برای تست: `php demo-seed.php`

## کلید امضای لایسنس (PACKAGE_LICENSE_SIGNING_KEY) — الزامی برای نصب/بروزرسانی پکیج‌ها

هر پاسخ لایسنس و مانیفست یکپارچگی (`verify-license`، `manifest`) با کلید خصوصی **EC P-256** امضا می‌شود.
اگر این کلید در `.env` تنظیم نشده باشد، کلاینت (فروشگاه) موقع نصب/بروزرسانی پکیج این خطا را می‌بیند:

```
نصب «X» ناموفق بود. (کلید امضای لایسنس (PACKAGE_LICENSE_SIGNING_KEY) تنظیم نشده است.)
```

### راه سریع (فرمان artisan — روی سرور آپدیت‌سنتر)

```bash
php artisan license:generate-signing-keys --write-env
php artisan config:clear
```

فرمان جفت‌کلید می‌سازد، خط `PACKAGE_LICENSE_SIGNING_KEY` را در `.env` می‌نویسد و کلید عمومی را چاپ می‌کند.
اگر کلید قبلاً تنظیم شده و می‌خواهید تعویض شود: `--force` اضافه کنید (هشدار: پاکت‌های امضاشدهٔ قبلی بی‌اعتبار می‌شوند — بخش «چرخش کلید بدون شکستن فروشگاه» را ببینید).

### راه پنلی (بدون شِل — هاست اشتراکی)

از پنل مدیریت: **تنظیمات → کلید امضای لایسنس** (`/admin/settings/license-key`)

- **ساخت کلید و ثبت در .env** — یک دکمه: جفت‌کلید EC P-256 ساخته، خط `PACKAGE_LICENSE_SIGNING_KEY` در `.env` نوشته و کش پیکربندی پاک می‌شود (معادل `config:clear` بدون شِل)
- **تعویض کلید** — با تأیید دومرحله‌ای؛ پاکت‌های قبلی بی‌اعتبار می‌شوند
- **پاک‌سازی کش پیکربندی** — اگر `.env` را دستی از File Manager ویرایش کرده‌اید
- نمایش وضعیت کلید (فعال / تنظیم‌نشده / نامعتبر)، اثرانگشت SHA-256 و کلید عمومی برای بکاپ
- **کپی خطِ `.env` فروشگاه** — صفحهٔ پنل، خط آمادهٔ `PACKAGE_LICENSE_PUBLIC_KEY="..."` متناظر با کلید فعلی را با دکمهٔ کپی نشان می‌دهد
- کلید خصوصی هرگز در پنل نمایش داده نمی‌شود — فقط در `.env` می‌ماند
- **داشبورد** وقتی کلید تنظیم‌نشده/نامعتبر باشد، هشدار قرمز با لینک همین صفحه نشان می‌دهد

### راه دستی (بدون artisan)

```bash
openssl ecparam -name prime256v1 -genkey -noout -out private.pem
openssl ec -in private.pem -pubout -out public.pem
```

سپس در `.env` (تک‌خطی با `\n` — سرویس امضا نرمال‌سازی می‌کند):

```
PACKAGE_LICENSE_SIGNING_KEY="-----BEGIN PRIVATE KEY-----\nMHc...\n-----END PRIVATE KEY-----\n"
```

و در پایان حتماً:

```bash
php artisan config:clear
```

### نکات مهم

- **بکاپ:** کلید خصوصی ریشهٔ اعتماد سیستم لایسنس است؛ از آن بکاپ امن نگه‌دارید. گم‌شدن یا تعویض آن یعنی همهٔ پاکت‌های قبلی بی‌اعتبار می‌شوند.
- فرمت‌های پذیرفته‌شده در `.env`: PEM چندخطی داخل کوتیشن، یا تک‌خطی با دنباله‌های `\n`، یا همان مقدار داخل کوتیشن اضافی — سرویس امضا هر سه را نرمال‌سازی می‌کند.

### چرخش کلید بدون شکستن فروشگاه (PACKAGE_LICENSE_PUBLIC_KEY)

فروشگاه (shop-pro-laravel-13) امضای این سرور را با «کلید عمومی» راستی‌آزمایی می‌کند.
اگر کلید خصوصی این‌جا عوض شود ولی کلید عمومیِ جدید در `.env` فروشگاه ثبت نشده باشد،
امضاهای جدید تأیید نمی‌شوند و پکیج‌های فروشگاه بسته می‌شوند:

```
امضای پاسخ سرور معتبر نیست / مانیفست یکپارچگی یافت نشد یا امضای آن معتبر نیست
```

**ترتیب امن:**

1. از پنل (**تنظیمات ← کلید امضای لایسنس**) خط آمادهٔ `PACKAGE_LICENSE_PUBLIC_KEY="..."` را کپی کنید.
2. آن را در `.env` فروشگاه بگذارید و `bootstrap/cache/config.php` فروشگاه را حذف کنید.
3. حالا در این‌جا «تعویض کلید» را بزنید.
4. گاردِ فروشگاه خودش ترمیم می‌کند: مانیفستِ تازه از این سرور provision می‌شود و پاکتِ جدید در چک آنلاین بعدی پذیرفته می‌شود.

در دورهٔ گذار، کلید عمومی قبلی را می‌توان در `PACKAGE_LICENSE_PUBLIC_KEY_PREVIOUS` فروشگاه نگه داشت
(امضا با هر یک از کلیدهای مورد اعتماد پذیرفته می‌شود). جزئیات کامل: README فروشگاه، بخش «چرخش کلید امضا».
